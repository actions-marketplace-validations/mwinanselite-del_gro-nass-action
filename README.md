# gro-nass — GitHub Action

Run the [`gro-nass`](https://www.npmjs.com/package/gro-nass) change harness on every push: refuse
attribution stamps, verify the ledger's hash chain and signatures, and replay recent commits through
the gate. Every receipt lands in `$GITHUB_STEP_SUMMARY`, so the verdict is the first thing a
reviewer sees rather than something they scroll a log to find.

```yaml
name: gate
on: [push]

jobs:
  gro-nass:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }     # replay reads history
      - uses: mwinanselite-del/gro-nass-action@v0.5.3
        with:
          version: "0.5.3"      # pin it — an action that floats changes its verdict under you
          replay: "20"               # 0 to skip
          fail-on-refusal: "true"    # false to observe before you enforce
```

## It runs the checks that exist

There is no `gro-nass wrap --check`. `wrap` lands a commit, and its message checks are
`--check-message`, which needs a message file a push does not have. On a push the commits are
already made, so what remains verifiable is what they carry: `check-stamps`, `verify-chain` and
`replay`.

## It cannot sign, by design

CI holds no owner key. A workflow that could sign rows would be a workflow whose token is the
owner's identity. This verifies what is already signed, and says so when something is unsigned that
should not be.

## This repository is generated

`action.yml`, this README and `LICENSE` are written from a single source in the harness
repository, and a test there refuses its own tree if any byte here differs. **Edits made here are
overwritten.** The same Action also appears under `github-action/` in
[`gro-nass-shelves`](https://github.com/mwinanselite-del/gro-nass-shelves) alongside the agent
listings; these are the same generated bytes, and this repository exists because GitHub resolves
`uses: owner/repo@ref` to `action.yml` at the repository ROOT.
